Kuhn meshes

How a cube is cut into tetrahedra, why the pieces fit together, and how bisection refines them without ever breaking that fit.

1. Sorting the coordinates

Take the unit cube and a point u = (u₀, u₁, u₂) in it. Sort the three coordinates from largest to smallest. There are 3! = 6 possible orders, and each order is a tetrahedron:

Tσ = { u : 1 ≥ uσ0 ≥ uσ1 ≥ uσ2 ≥ 0 }

Its corners are found by walking from (0,0,0) to (1,1,1) along cube edges, stepping first in direction σ0, then σ1, then σ2:

x₀ = 0,   x₁ = eσ0,   x₂ = eσ0 + eσ1,   x₃ = (1,1,1)

The six orders tile the cube exactly: every point has a (generically unique) sorted order, and points where two coordinates tie lie on a shared face. All six tetrahedra share the main diagonal x₀x₃, and each has volume 1/6.

2. Locating a point is a sort

To find which tetrahedron of an n×n×n grid contains a point x, take the cell c = ⌊n x⌋ and the local coordinates u = n x − c, then sort u. The sorted values also give the barycentric coordinates directly, with no linear solve:

λ = ( 1 − u[σ0],  u[σ0] − u[σ1],  u[σ1] − u[σ2],  u[σ2] )   # weights of x0, x1, x2, x3

Vectorized over many points, this is one argsort, a lookup of the permutation, and four subtractions per point.

3. Why neighbouring cells fit together

A triangulation is conforming when two tetrahedra meet in a full shared face, edge or vertex, or not at all; there are no hanging vertices or partly overlapping faces. P1 finite elements need this so the piecewise-linear map is continuous.

In the Kuhn triangulation every face lies on a plane of the form xi = k/n or xi − xj = k/n. Every cell uses the same orientation, so on a shared square face both neighbours cut along the same diagonal (the one parallel to ei + ej). The two sides match automatically.

The same plane argument shows that the Kuhn mesh at 2n refines the one at n: within a fine cell each ui − uj has a fixed sign, so a fine tetrahedron never straddles a coarse plane. The meshes are nested.

4. Refining by bisection

For adaptive refinement we cut one tetrahedron at a time instead of a whole grid. Maubach's bisection rule keeps everything consistent. Each tetrahedron carries its vertex order (x₀, x₁, x₂, x₃) and a tag k ∈ {1,2,3}. Kuhn tets start with k = 3.

  1. The refinement edge is x₀xk, and z is its midpoint.
  2. The children are (x₀, …, xk−1, z, xk+1, …) and (x₁, …, xk, z, xk+1, …).
  3. Both children get tag k − 1, or 3 when k = 1.

The first cut splits the main diagonal. Three generations later, each Kuhn tetrahedron has become 8 tetrahedra of half the size that are again Kuhn path-simplices. They are reflected: in each half-size subcell the path runs from whichever corner the reflection dictates, not always from the lower-left one. The pattern then repeats, every 3 generations, forever.

Shapes of the pieces

Not every piece has the original shape, but only three shapes ever occur. Every generation consists of a single shape, and the shapes cycle with period 3 (counted up to rotation, reflection and scaling). With h the side of the original cube, and generation g + 3 always being generation g at half the size:

GenerationEdge lengths (at generation 0, 1, 2)Unique longest edge
0, 3, 6, …h, h, h, √2 h, √2 h, √3 h√3 h, a cube diagonal
1, 4, 7, …½√3 h ×3, h ×2, √2 h√2 h, a face diagonal
2, 5, 8, …½ h, ½√2 h ×2, ½√3 h ×2, hh, a cube edge
  • Same shape as the original? Only every third generation. Generations 3k are exact copies of the original Kuhn tetrahedron scaled by 2−k. The two generations in between have the other two shapes.
  • Unique longest edge? Always. Moreover the refinement edge x₀xk is always that longest edge, so on Kuhn meshes Maubach's rule is the same as longest-edge bisection.
  • No degeneration. With only three shapes, angles stay bounded away from 0 and π however deep the refinement goes. Each bisection halves the volume.

All of this was checked exactly, with rational arithmetic, for generations 0–9 of all six Kuhn tetrahedra. Shapes were compared through their full distance matrices over all 24 vertex relabellings.

Local refinement and closure. When only some tetrahedra are bisected, a neighbour that shares the cut edge now has a midpoint sitting in the middle of one of its edges (a hanging vertex). The fix is a closure loop: keep bisecting every leaf that has a midpoint on one of its edges until none is left. For meshes that start from a consistently tagged Kuhn grid this loop always terminates, and the result is conforming again.

Does the order of bisections matter? No. A tetrahedron's children depend only on that tetrahedron (its vertex order and tag), not on when it is cut. So every mesh we can ever produce is a set of leaves of one fixed binary tree per root. The closure loop cuts a leaf only when a midpoint already sits on one of its edges, and every conforming mesh containing the requested cuts must make that cut too. The result is therefore always the unique coarsest conforming mesh containing the requested bisections, whatever order they were made in.
